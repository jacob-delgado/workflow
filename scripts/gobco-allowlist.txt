# The condition arms no test can reach. The gate is scripts/gobco-report.sh
# (task cover:branch), which fails on any condition never evaluated, on any
# error check whose error arm was never seen, and on any condition seen one
# way on a line the change touched, unless a line here keeps it; the format
# and the matching are in scripts/lib/gobco-arms.awk's header.
#
# ONE LINE PER ARM, under a comment that says why no test can reach it:
#
#     <file> <function> <systems> <number> <condition>
#
# <function> is as the gate prints it, Type.Method for a method. <systems> is
# "any", or the GOOS values on which the arm goes unseen, joined by commas.
# <number> is the arm's place among the conditions of its function that read
# the same, counted from the top, as the gate prints it, and <condition> is
# the code gobco prints for it.
#
# Every other arm the gate names is a test to write, not a line to add. A line
# keeps any arm of its condition, since one only another system sees both
# ways may be kept on a line a change touches, so a line fails the gate until
# it is removed once a test sees its condition both ways, and this list
# shrinks as tests arrive; one kept for an arm a test comes to reach stays
# while the other arm goes unseen, since a line does not name its arm. Source
# lines are not named here: they drift, and the gate matches on file,
# function, number and condition.
# The number keeps a kept arm that a test comes to reach from being traded for
# a new one no test reaches that reads the same, added below it. A condition
# that reads the same added above a kept arm moves its number on, and the gate
# fails until the line follows it, but for one case: when a test comes to
# reach the kept arm in the same change, the new arm takes its number and the
# line keeps it, unseen, since without source lines the two read alike.

# Encoding the program's own types is taken not to fail, nor decoding JSON the
# program just encoded or decoded; and, in the web server, a caller that only
# passes such a failure on. The values hold only strings, integers, booleans,
# finite floats, slices and maps of the same, or values just decoded from
# JSON, and a config.Config's JSON always fits api.Config, so no test can make
# one fail; each arm stays so a failure is reported, or, in config's own
# encoders, panics, rather than being read past. A type encoded here that
# gains a float that can be NaN or infinite, a func, a channel, an interface
# field or a MarshalJSON of its own puts its arm in play, and needs a test.
