# Per-directory file budgets. The gate is scripts/check-package-size.sh; the
# metric and its reasoning live in that script's header.
#
# ONE ENTRY PER LINE:
#
#     <repo-relative dir>   <budget>|exempt
#
# Every entry MUST carry a `#` comment on the line(s) DIRECTLY above it saying
# why the number is that number — not what the directory is. The script fails
# on an entry without one.
#
# A DIRECTORY NOT LISTED answers to DEFAULT_MAX_FILES, which lives in the
# script and is deliberately NOT restated here: a number spelled in two places
# is exactly the drift this gate exists to catch. Run
# `scripts/check-package-size.sh --list` to see it applied. That default is the
# standing decision — no grouping grows past it without a written reason — not
# an escape hatch. Registration is earned by size, which is what keeps this file
# short and every line in it load-bearing. Deleting an entry does not dodge the
# gate: an over-budget directory falls back to the default and fails harder.
#
# BUDGETS ARE ZERO-HEADROOM IN BOTH DIRECTIONS. A file count only moves when
# someone deliberately creates a file, which is exactly the moment worth a
# thought — so a budget is the count on the day it was registered, and the next
# file trips the gate. A budget left ABOVE its count fails too; that is what a
# forgotten post-split ratchet looks like.
#
# Counts here are SOURCE files: unit tests (`*_test.go`, `*.test.ts(x)`),
# stylesheets (`*.css`) and generated code (`*.gen.go`, a whole generated tree
# marked `exempt`) do not count. But integration tests (`*_integration_test.go`)
# and everything under `web/e2e/` (Playwright specs and helpers) DO count — an
# end-to-end surface piles up one scenario at a time, and the budget is what
# forces it into per-surface folders instead of a hundred files in one. The
# budget measures concerns, not artifacts.

# internal/config — the .workflow.json loader, one file per config section: the
# root Config with its load and save (config.go, load.go, save.go), credential
# redaction and secret resolution (redact.go, secret.go), the messaging mode
# rules (modes.go), and a file per configurable section, each carrying its own
# validation — branch, commit, pull_request, store, timing, ui, version and
# views. One responsibility (read and validate the configuration) spelled
# section-per-file; it grows only when a feature adds a section, which is a
# deliberate decision. 13 registered pull_request.go (FEAT-14) and store.go
# (FEAT-67) as they crossed the default budget; 14 is ui.go, the terminal's
# section moved out of config.go to carry the validation it had gone without.
internal/config 14

# internal/tui — the Bubble Tea interface, one file per pane, overlay and
# composer. It is a single responsibility (drive the terminal UI) spelled
# file-per-concern: every file hangs its behavior off the one shared Model, so
# the package cannot be split without threading that Model — and the methods on
# it — across a package boundary Go does not allow. This is the cohesive package
# CLAUDE.md names as one that must not be split to chase a number; the entry
# freezes the count so a new concern is a decision, not drift, not a target to
# shrink toward. layout/ and frame/ are already the pure leaves that could leave.
# 41 = the panes, overlays and composers, including issuewrite.go (the assign
# and log-work forms), issuekeys.go (the Issues pane's key routing, split out of
# detail.go when it crossed the 500-line file ceiling), scopesuggest.go (the
# commit scope's completion from the staged directory and the log) and diff.go
# (the Commits pane's diff preview), each kept beside commits.go/composer.go
# rather than swelling either toward the 500-line ceiling; finish.go (the
# Review pane's finish-a-merged-branch preview and its git cleanup), split out
# of review.go when merge and finish together pushed it past the 800-line hard
# ceiling; preditor.go (the Review pane's edit-an-open-pull-request overlay —
# title and description — kept a dedicated overlay rather than an edit-mode
# flag bolted onto composer.go); merge.go (the Review pane's merge picker and
# its permitted-methods read, split out of review.go when it passed the
# 500-line target, the re-run moving to checks.go beside the checks it acts
# on); messagingpreview.go (the Messaging pane's announcement preview and its
# send, split out of messaging.go when it passed the 500-line target); and
# prcreate.go (opening the pull request the composer describes — the push
# first, the create, then the link and status offers — split out of
# prcomposer.go for the same reason).
internal/tui 41

# internal/webserver — the loopback REST surface: a file per write (announce,
# branchcreate, checkout, commit, config, pullrequest, push), or per pair of
# writes that share their checks (issuewrite: link the pull request and move the
# issue; staging: stage and unstage), beside handlers.go, which holds the reads
# no write owns (a write's own read — the draft, the announcement, the config —
# sits in its file); stream.go (the event stream), static.go (the embedded app),
# dto.go (the wire shapes), validator.go (the contract check), guard.go and
# errors.go (the loopback and dry-run guards and the RFC 9457 errors), and
# webserver.go (the server and its seams). One responsibility (turn a guarded
# request into a seam call and a DTO) spelled handler-per-operation; like
# internal/tui it is cohesive and grows only when the API gains an operation,
# which is a decision the OpenAPI spec records first. 17 = staging.go, the web's
# stage and unstage — one changed file, or all of them — which the terminal
# makes with space and a. Frozen here so that growth stays deliberate.
internal/webserver 17
