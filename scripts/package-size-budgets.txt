# Per-directory file budgets. The gate is scripts/check-package-size.sh; the
# metric and its reasoning live in that script's header.
#
# ONE ENTRY PER LINE, of one of three kinds:
#
#     <repo-relative dir>   <budget>              a ratcheted budget
#     <repo-relative dir>   <ceiling> cohesive    a cohesive ceiling
#     <repo-relative dir>   exempt                not counted at all
#
# Every entry MUST carry a `#` comment on the line(s) DIRECTLY above it saying
# why the number is that number — not what the directory is. The script fails
# on an entry without one.
#
# A DIRECTORY NOT LISTED answers to DEFAULT_MAX_FILES, which lives in the
# script and is deliberately NOT restated here: a number spelled in two places
# is exactly the drift this gate exists to catch. Run
# `scripts/check-package-size.sh --list` to see it applied. That default is the
# standing decision — no grouping grows past it without a written reason — not
# an escape hatch. Registration is earned by size, which is what keeps this file
# short and every line in it load-bearing. Deleting an entry does not dodge the
# gate: an over-budget directory falls back to the default and fails harder.
#
# A RATCHETED BUDGET IS ZERO-HEADROOM IN BOTH DIRECTIONS. A file count only
# moves when someone deliberately creates a file, which is exactly the moment
# worth a thought — so a budget is the count on the day it was registered, and
# the next file trips the gate. A budget left ABOVE its count fails too; that is
# what a forgotten post-split ratchet looks like.
#
# A COHESIVE CEILING is for a grouping that is file-per-concern BY DESIGN: one
# responsibility spelled one file per pane, per endpoint or per command, which
# grows by a file each time the surface gains one and which CLAUDE.md says must
# not be split to chase a number. Zero headroom there was a ritual — every bump
# gave the same WHY and none ever led to a split — so such a grouping answers
# to a ceiling instead: it fails only past it, has no ratchet, and its comment
# names the spelling rule that makes it cohesive rather than listing its files.
# Raising a ceiling is a decision like any bump: rewrite the WHY and append a
# row to scripts/package-size-budget-history.md.
#
# Counts here are SOURCE files: unit tests (`*_test.go`, `*.test.ts(x)`),
# stylesheets (`*.css`) and generated code (`*.gen.go`, a whole generated tree
# marked `exempt`) do not count. But integration tests (`*_integration_test.go`)
# and everything under `web/e2e/` (Playwright specs and helpers) DO count — an
# end-to-end surface piles up one scenario at a time, and the budget is what
# forces it into per-surface folders instead of a hundred files in one. The
# budget measures concerns, not artifacts.
